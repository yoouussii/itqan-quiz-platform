## 🌟 نظرة عامة على المنصة
**منصة إتقان التعليمية** هي منصة متكاملة لإدارة التقييمات والاختبارات المدرسية مبنية بالكامل بنمط القراءة العربي من اليمين إلى اليسار (RTL-first design) مع دعم الوضعين النهاري والليلي (Light / Dark Mode)، ونظام دخول آمن موحد عبر **رقم الهوية الوطنية / الرقم الأكاديمي**، مع حظر التسجيل العام لحماية خصوصية المؤسسة التعليمية.

---

## 🚀 التحديثات والمميزات الرئيسية

### 1. نظام الدخول برقم الهوية وإلغاء التسجيل العام (Secure Institutional Access)
- تم استبدال البريد الإلكتروني بـ **رقم الهوية الوطنية / الرقم الأكاديمي (National ID / Academic ID)** كمفتاح أساسي لتسجيل الدخول.
- **إلغاء التسجيل العام نهائياً:** لا يمكن لأي مستخدم إنشاء حساب خارجي؛ يتم إنشاء كافة الحسابات وتوزيع الصلاحيات حصراً عبر المشرف العام (Admin) من لوحة إدارة المستخدمين.

### 2. لوحة إدارة المستخدمين والصلاحيات الدقيقة (Admin User & Granular RBAC)
- **لوحة تحكم كاملة (CRUD):** إضافة مستخدم جديد، تعديل البيانات، إعادة تعيين كلمة المرور، وحذف الحسابات.
- **تبديل وترقية الأدوار (Role Promotion & Switching):** إمكانية ترقية المعلم لمدير نظام أو نقل الطلاب وتعديل فصولهم.
- **الصلاحيات الدقيقة للمعلمين (Granular Teacher Permissions):**
  1. `can_add_custom_subjects`: صلاحية إضافة مواد دراسية مخصصة.
  2. `can_manage_classes`: صلاحية إدارة الفصول والشعب وتعديل مسمياتها.
  3. `can_view_all_reports`: صلاحية الاطلاع على تقارير المدرسة الشاملة بدلاً من اختباراته فقط.

### 3. إدارة المواد والشعب المخصصة (Dynamic Custom Subjects & Classes)
- إمكانية إضافة وتعديل وحذف المواد الدراسية والشعب بأسماء ونصوص مخصصة دون قيود مسبقة.

### 4. حماية صارمة لخصوصية الطلاب (Strict Privacy Protection)
- **عزل تام للنتائج:** لا يمكن لأي طالب رؤية أسماء أو درجات أو أوراق إجابة زملائه.
- يرى الطالب حصراً الاختبارات الموجهة لصفه أو لشخصه، وتقارير أداءه الشخصية فقط.

### 5. الوضع الليلي والنهاري (Dark / Light Theme)
- زر تبديل سلس في الشريط العلوي مع حفظ تلقائي للتفضيل في `localStorage` وتوافق لوني فائق الجمال لكافة الجداول والمخططات البيانية.

### 6. صور وأيقونات قياسية موحدة (Clean SVG Avatars)
- استبدال كافة روابط الصور الخارجية بمونوغرامات وشارات SVG قياسية ملونة وفق دور المستخدم (أرجواني للمدير، أخضر للمعلم، وعنبري للطالب).

## 💻 التشغيل والتطوير المحلي

### ربط Supabase
1. انسخ `.env.example` إلى `.env` وضع فيه `VITE_SUPABASE_URL` و`VITE_SUPABASE_ANON_KEY`.
2. من **SQL Editor** في لوحة Supabase شغّل:
   - `supabase/migrations/002_users_columns.sql`: **مطلوب** لحفظ إسنادات وصلاحيات المشرف والمعلم على الخادم (يضيف الأعمدة الناقصة ويسمح بدور `supervisor`).
   - `supabase/migrations/001_v8_tables.sql`: للتثبيت الجديد فقط (جداول الإشعارات والسجل والجوائز والإعدادات والصور). إن كانت موجودة عندك فلا حاجة له.

### تفعيل الحماية (supabase/migrations/003_security)
1. انشر نسخة الموقع الجديدة أولاً (تعمل قبل الملف وبعده).
2. **الطريقة الموصى بها:** من GitHub ← Actions ← **Supabase migrate** ← Run workflow ← اختر `003_security_all.sql` (يتطلب السر `SUPABASE_DB_URL`: رابط Session pooler من زر Connect في Supabase). يعمل في معاملة واحدة: ينجح كاملاً أو لا يتغير شيء.
   أو يدوياً: شغّل الملف الكامل `supabase/migrations/003_security_all.sql` في استعلام واحد، أو بدلاً منه الأجزاء `part1.sql` ← `part5.sql` من مجلد `supabase/migrations/003_security` بالترتيب، كل جزء في استعلام جديد (New query) في SQL Editor:
   - افتح الملف على GitHub ← زر **Raw** ← `Ctrl+A` ثم `Ctrl+C`، والصقه في استعلام فارغ ثم **Run** دون تحديد أي جزء من النص.
   - يجب أن تظهر في النتيجة «✓ تم الجزء N من 5». إن ظهر خطأ فالنص لم يُنسخ كاملاً: أعد نسخ نفس الجزء وشغّله (آمن لإعادة التشغيل).
3. سيُطلب من الجميع تسجيل الدخول مرة واحدة من جديد، بنفس كلمات المرور.
4. تأكد من الدخول بحساب مدير وطالب. عند أي مشكلة: شغّل `003_rollback.sql` (يوقف سياسات الحماية فقط).

بعد التفعيل: كلمات المرور مشفّرة، والطالب لا يرى إلا بياناته، والتصحيح على الخادم، والإجابات النموذجية مخفية حتى التسليم.

### تحديث 004: مؤقت الاختبار وإخفاء الإجابات وصلاحيات التعديل
بعد نشر الموقع شغّل من Actions ← **Supabase migrate** الملف `004_timer_answers_permissions.sql`:
- وقت بدء الاختبار يُسجَّل على الخادم: تحديث الصفحة يكمل نفس المؤقت ونفس الإجابات.
- الإجابات النموذجية تظهر للطالب بعد انتهاء وقت إتاحة الاختبار (لا فور التسليم).
- المعلم يعدّل ويحذف اختباراته فقط (المدير ومن يملك صلاحية الاعتماد: الكل).

### تحديث 005: حذف الإشعارات
شغّل من Actions ← **Supabase migrate** الملف `005_notification_delete.sql`:
- كل مستخدم يحذف إشعاراته من عنده (تختفي من كل أجهزته).
- المدير: «إدارة إشعارات النظام» في صفحة الإشعارات (حذف نهائي، حذف جماعي، مسح إشعارات مستخدم).
- مُرسل الإعلان يحذفه من عند الجميع.

### تحديث 006: بانرات الصفحة الرئيسية
شغّل من Actions ← **Supabase migrate** الملف `006_banners.sql`، ثم من قائمة «المزيد» ← **بانرات الصفحة الرئيسية**:
- صورة عريضة بعرض الصفحة مع عنوان ونص، أو معرض صور طلاب (حتى 10) مع الاسم تحت كل صورة.
- لمن يظهر (الجميع / الطلاب / الطاقم)، وتاريخ ظهور واختفاء تلقائي، وترتيب، وإخفاء مؤقت.
- الصور تُصغَّر تلقائياً وتُنزَّل مرة واحدة لكل جهاز (لا مع كل تحديث).

### تحديث 007: حذف مشاركات الطلاب
شغّل من Actions ← **Supabase migrate** الملف `007_delete_submissions.sql`:
- في جدول النتائج: زر حذف لكل مشاركة، وتحديد وحذف جماعي، وحذف مشاركات الاختبارات المحذوفة بضغطة.
- الحذف للمدير ولمن يُمنح صلاحية «حذف مشاركات الطلاب»؛ بعد الحذف يستطيع الطالب دخول الاختبار مرة أخرى إن كان متاحاً.

### تحديث 008: فرض اعتماد الاختبارات
شغّل من Actions ← **Supabase migrate** الملف `008_quiz_approval.sql`:
- المعلم الذي لا يملك صلاحية «اعتماد الاختبارات» لا يستطيع نشر اختبار مباشرة: يُحفظ «بانتظار الاعتماد» على الخادم نفسه.
- الاشتراط مفعّل افتراضياً، ويُلغى من «الإعدادات». ينشئ جدول الإعدادات `app_settings` إن لم يكن موجوداً.
- في بنك الاختبارات زر «سحب للمراجعة» لإيقاف اختبار منشور وإعادته للاعتماد.

### تحديث 009: الفروع وأولياء الأمور والنوع
شغّل من Actions ← **Supabase migrate** الملف `009_branches_parents.sql` (بعد 008):
- **الفروع:** يضيفها المدير من «المواد والشعب» ← تبويب «الفروع»، ويُسندها للمستخدمين (فردياً أو بالتحديد الجماعي «نقل للفرع») وللشعب. المعلم أو المشرف المسند لفرع يرى فرعه فقط، ومن بلا فرع يرى الكل.
- **أولياء الأمور:** دور «ولي أمر» مرتبط بأبنائه، يتابع اختباراتهم ونتائجهم ونقاطهم فقط. يُنشأ من نموذج المستخدم أو تلقائياً عند استيراد Excel بعمودي «هوية ولي الأمر» و«كلمة سر ولي الأمر» (حساب واحد لكل هوية باسم «والد الطالب …»).
- **النوع:** ذكر/أنثى في نموذج المستخدم وعمود «النوع» في Excel، مع تصفية في المستخدمين والنتائج.
- أعمدة Excel الجديدة الاختيارية: النوع، الفرع، هوية ولي الأمر، كلمة سر ولي الأمر.

### تحديث 010: الشعب المشتركة
شغّل `010_unassigned_classes_visible.sql` بعد 009: الشعبة غير المربوطة بفرع يراها كل المعلمين (كانت تختفي عن معلم الفرع فتظهر صفحة إنشاء الاختبار بلا شعب). وأُلغي خيار «جميع الطلاب» من استهداف الاختبار.

### تحديث 011: الشعب والمواد مشتركة بين كل الفروع
شغّل `011_shared_classes.sql` بعد 010: كل الشعب تصبح مشتركة (المواد مشتركة أصلاً)، فأي فرع جديد يجد نفس الشعب والمواد جاهزة، واختيار فرع الشعبة أُزيل من الواجهة. اختبار معلم الفرع يصل لطلاب فرعه فقط في الشعبة المختارة.

### تحديث 012: هوية المدرسة
شغّل `012_school_branding.sql`: يعرض اسم المدرسة وشعارها ولونها في شاشة الدخول. تُضبط من **الإعدادات ← هوية المدرسة**.

### تحديث 013: خيارات البانر
شغّل `013_banner_options.sql`: خيار «دائم» (بانر بدون زر إخفاء) وتأثيرات احتفالية تخرج من البانر (قصاصات، بالونات، نجوم، كؤوس).

### تحديث 014: الحد من الغش
شغّل `014_quiz_integrity.sql`: ثلاث خيارات في محرر الاختبار (ترتيب مختلف للأسئلة لكل طالب، ترتيب مختلف للاختيارات، وضع ملء الشاشة)، وتسجيل عدد مرات خروج الطالب من صفحة الاختبار ومدته في كل الاختبارات، ويظهر للمعلم في النتائج وورقة الإجابة. قبل تشغيله تعمل المنصة كما كانت (التسليم بدون السجل).

### اللغة الإنجليزية
زر **EN / ع** في شاشة الدخول وأعلى الصفحات، والاختيار يُحفظ على جهاز كل مستخدم. الواجهة مترجمة لكل الأدوار: الطالب وولي الأمر والمعلم والمشرف والمدير.
- النص العربي نفسه هو مفتاح الترجمة: `t('نتائجي')`، والترجمات في `src/i18n/en.ts`.
- `node scripts/i18n-check.mjs` يعرض النصوص التي لا ترجمة لها، ومع `--raw <ملف>` النصوص العربية التي لم تُغلَّف بعد.
- `python3 scripts/i18n-wrap.py <ملفات>` يغلّف نصوص JSX تلقائياً، و`scripts/rtl-logical.py` يحوّل أصناف left/right إلى start/end.
- محتوى الاختبارات (الأسئلة وأسماء المواد) يبقى كما كتبه المعلم ويأخذ اتجاه لغته تلقائياً.

### إعداد مدرسة جديدة
خطوات كاملة في [docs/NEW_SCHOOL.md](docs/NEW_SCHOOL.md): قاعدة بيانات Supabase جديدة، ثم **Actions ← Setup new school** (ينشئ الجداول والحماية وحساب المدير)، ثم مشروع Vercel من نفس المستودع.

### روابط الصفحات
لكل صفحة رابط خاص (مثل `/results` و`/quiz/<رقم>`)، فيعمل زر الرجوع والتحديث وفتح الصفحة في تبويب جديد. من قائمة الاختبار اختر «نسخ رابط الاختبار للطلاب» وأرسله لهم: يسجّل الطالب دخوله فيفتح الاختبار مباشرة. ملف `vercel.json` يوجّه كل الروابط إلى الموقع.

### تشغيل مجاني بدون باقة Pro (GitHub Actions)
أضف من **Settings ← Secrets and variables ← Actions** في GitHub:
`SUPABASE_URL` و`SUPABASE_ANON_KEY` و`SUPABASE_SERVICE_ROLE_KEY` (من Supabase: Project Settings ← API؛ سرّي جداً ولا يوضع في الموقع) و`BACKUP_PASSPHRASE` (كلمة سر طويلة تحفظها عندك لفك النسخ).
- **Supabase keep-alive**: يتصل بالمشروع كل 3 أيام فلا تُوقفه الخطة المجانية في الإجازات.
- **Supabase backup**: نسخة احتياطية مشفّرة كل جمعة تُحفظ 90 يوماً في صفحة Actions. فك التشفير:
  `gpg -d itqan-backup.tar.gz.gpg > backup.tar.gz && tar xzf backup.tar.gz`

ملاحظة: المهام المجدولة تعمل من الفرع الرئيسي فقط، ويُوقفها GitHub إن مرّ 60 يوماً بلا أي تعديل على المستودع (يُعاد تفعيلها بزر من صفحة Actions).

```bash
# تثبيت الاعتماديات
npm install

# تشغيل خادم التطوير
npm run dev

# بناء النسخة الإنتاجية
npm run build

# معاينة النسخة الجاهزة للإنتاج
npm run preview
```
